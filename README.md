# Polarisark Product Beautifier

> 为需要电商商品图的用户，将一张或多张商品实拍图独立精修为真实、明亮通透、材质分明的白底成片。

**效果示例（示意）：** 背景杂乱、曝光偏暗的商品原图 → 保持原机位、商品结构与原色的白底图，并附逐图处理摘要和批次结果。

## 1. 快速开始

**使用前准备：** 支持 Agent Skills 的宿主、一张可读取的商品实拍图，以及可用的图像编辑能力。默认使用宿主能力，无需 API 配置；宿主没有图像编辑能力时，可配置本 Skill 的 API 通道。

### 安装

本 Skill 基于开放的 [Agent Skills 协议](https://agentskills.io/specification)。支持该协议的宿主可读取技能，实际精修还需满足上述图像编辑条件。

打开你正在用的 Agent，告诉它：

```text
帮我安装这个 skill：https://github.com/jonathansong21/polarisark-product-beautifier
```

或者使用通用 CLI 安装器 [vercel-labs/skills](https://github.com/vercel-labs/skills)：

```bash
npx skills add jonathansong21/polarisark-product-beautifier
```

安装器支持检测本机宿主并选择安装目标。默认安装到当前项目；需要用户级全局安装时加 `-g`，指定宿主时加 `-a codex` 或 `-a claude-code` 等参数。其他标识见[支持列表](https://github.com/vercel-labs/skills#supported-agents)。例如，全局安装到 Codex：

```bash
npx skills add jonathansong21/polarisark-product-beautifier -g -a codex
```

`agents`、`references` 和 `scripts` 分别提供界面元数据、精修与 API 指南、API 调用能力；用户配置独立保存在包目录外。

### 第一次调用

在 Codex 中附上 `photo.jpg` 商品实拍图，并输入：

```text
使用 $polarisark-product-beautifier 精修这张 photo.jpg，输出电商白底图。
```

**预期结果：** 通过 QA 后返回成片及摘要，例如实际成片为 PNG 时：

```text
photo_beautified.png
处理摘要：清理背景，校正曝光与白平衡，保持商品结构和原色。
批次结果：成功 1，失败 0。
```

**确认成功：** 成片可打开，与原图为同一商品；背景为白色，默认采用 1:1 构图和极轻自然接触阴影，商品完整且关键细节未改变。


## 2. 适用场景与能力边界

**适合以下任务：**

- 一张或多张商品实拍图 → 按输入顺序逐张独立精修，同批可包含不同 SKU。
- 灰尘、指纹、支架、背景残留或色污染 → 清理已确认属于拍摄环境的问题。
- 曝光、白平衡、轻微倾斜、畸变、边缘或阴影问题 → 校正摄影呈现，保持原机位与商品事实。
- 织物、皮革、塑料、玻璃、金属、木质、陶瓷和包装等商品 → 根据实际材质改善纹理、反射、光泽与体积感。

**能力边界：**

| 请求 | 处理方式 |
|---|---|
| 场景合成、广告创意图、模特图、非白底或透明背景 | 超出本 Skill 范围，不交付这些版本或中间资产。 |
| 换色、换款、重设计、增删配件、重绘 Logo 或标签 | 不按精修处理，保持原商品与原 SKU。 |
| 仅裁剪、压缩、改格式或重命名既有图片 | 属于机械图片处理，不使用本 Skill。 |
| 目标图与参考图角色、配件归属或售卖单元不清 | 先集中确认，再开始整批处理；不猜测结构、颜色、文字或被遮挡细节。 |
| 只提供平台名称，要求保证平台合规 | 不内置平台预设；需提供具体图片规范，不能仅凭平台名称声称合规。 |

**调用方式：** Codex 可显式使用 `$polarisark-product-beautifier`。当前 Codex 配置允许自动匹配“商品实拍图白底精修”等请求；其他宿主的调用与自动匹配方式以其支持情况为准。

## 3. 输入与输出

### 输入

| 输入项 | 必填 | 格式与示例 | 缺失时的处理 |
|---|---|---|---|
| 目标商品原图 | 是 | 可读取的图片附件或本地路径，如 `photo.jpg`；一张或多张 | 从已提供上下文读取；仍没有原图时请求补充。 |
| 图片角色与商品归属 | 有歧义时需要 | 标明哪些是目标图、哪些是关联参考图，哪些物体属于商品 | 单一明确商品可直接处理；歧义会影响真实性时先询问。 |
| 色卡、产品事实档案或参考图 | 否 | 明确关联到某张目标图，用于确认颜色与结构 | 以各自原图为事实来源，不精修或交付辅助资料。 |
| 构图、阴影、摆放与保存偏好 | 否 | 如“4:5、无阴影、链条摆放不变，保存到指定目录” | 默认 1:1、均衡留白、极轻接触阴影；通过宿主可用渠道返回。 |
| 通道与 API 参数 | 否 | 如“本次使用 API，模型与尺寸按已配置服务” | 按本次明确要求、本地配置、默认 `host` 的顺序选择。 |

**输入限制：** 多图按目标图输入顺序独立处理，参考图不参与目标编号。API 支持的图片格式、尺寸及参考图数量需与服务能力相符，详见 [API 编辑说明](references/api-edit.md)。

### 输出

| 交付物 | 格式 | 必含内容 | 保存或返回位置 |
|---|---|---|---|
| 通过 QA 的白底精修成片 | 图片，扩展名匹配实际格式 | 保持同一商品、原机位、结构与原色，满足背景和构图要求 | 用户指定目录或宿主可用的图片交付渠道。 |
| 逐图处理摘要或失败说明 | 简短文本 | 成功项说明处理内容；失败项说明具体问题、风险和必要补充材料 | 聊天中，按目标图输入顺序对应。 |
| 批次结果 | 简短文本 | 成功、失败数量；必要时单列结果未知和未处理项 | 聊天中。 |

**文件处理：** 不覆盖原图或已有文件。合格成片使用 `{原图文件名主体}_beautified.{实际扩展名}`；没有可用原图名时使用 `image_001_beautified.png` 等固定输入序号，实际扩展名随格式调整。参考图不参与编号，失败不改变后续序号。重名时追加 `_02`、`_03` 等编号；文件名不含纠正轮次。交付渠道无法落实实际文件名时会明确说明。

**部分完成：** 失败候选不标为合格成片。单图问题通常不影响后续目标；鉴权、余额、限流或整体能力不可用时停止剩余队列并列出未处理项。结果未知单独说明，不当作“未生成”。

## 4. 使用示例

以下为调用与交付格式示例，使用时须附上对应商品原图。

### 标准任务

**用户请求与素材：**

```text
使用 $polarisark-product-beautifier，独立精修以下两张目标原图：
1. 链条包.正面.jpeg：黑色链条包实拍，背景杂乱、曝光偏暗。
2. glass.jpg：透明玻璃杯实拍，背景有灰尘。
两张图属于不同 SKU，没有辅助参考图。
输出 1:1 白底图，保持颜色、结构、Logo 和文字；链条摆放不变。
```

**预期输出：** 两张图均通过 QA 且实际成片为 PNG 时：

```text
1. 链条包.正面_beautified.png
   清理背景并校正曝光，保持黑色、包体结构与链条摆放。
2. glass_beautified.png
   清理背景灰尘，保留玻璃杯轮廓、透明边线与自然高光。
批次结果：成功 2，失败 0。
```

**检查要点：** 两张图独立对应原 SKU；包体和链条连接事实不变，链条位置符合用户要求；玻璃没有变浑浊或丢失边缘。示例文件名仅在实际格式为 PNG 时使用 `.png`。

### 边界任务

**请求：** 附上一张包含手包、肩带和摄影支架的图片，要求“去掉多余配件”，但未说明哪些物体属于售卖商品。

**处理：** 先确认肩带和支架的归属，例如：“肩带是否随商品出售？图中的支架是否仅为摄影道具？”确认后仅清理拍摄道具；不猜测或删除真实配件。

## 5. 工作流程与关键规则

1. 确认目标图、参考图和售卖单元，建立固定输入顺序，诊断商品事实、结构、材质与摄影问题。
2. 按本次要求和本地配置选择图像编辑通道，从当前目标原图生成候选，参考资料只作为真实性证据。
3. 对照原图检查结构、颜色、材质、背景、构图和阴影；有明确可修正问题时执行定向纠正。
4. 通过 QA 后落实成片名称并交付；未通过项说明问题，汇总整批结果。

**关键规则：**

- 背景固定为纯白 `#FFFFFF`；默认 1:1、均衡留白和极轻自然接触阴影，用户明确提供的比例与阴影要求优先。
- 保持原机位、透视、朝向、轮廓、比例、刚性几何、部件数量与连接关系、孔位、接口、Logo 和可见文字。
- 柔性部件可整理为自然陈列，但数量、顺序、拓扑、连接点和真实长度不变；要求“摆放不变”时也锁定相对位置。
- 保留真实磨损、划痕、褶皱、纹理和制造特征；只有用户确认属于不代表正常交付商品的样品损伤时，才可按要求处理。
- 每张图最多首轮生成加 3 次定向纠正；每次纠正重新使用该张原图，并保留累计纠正约束。通过即停止，仍不合格则说明失败。
- API 调用错误不自动重试，不静默更换服务商、模型或通道。已配置的 API 默认方式或本次明确选择即可使用相应通道；仅发现密钥不构成 API 授权。修改默认配置须由用户明确要求。

完整执行规则以 [SKILL.md](SKILL.md) 为准；README 概括使用者需要了解的行为。

## 6. 环境依赖与配置

| 依赖 | 是否必需 | 用途 | 版本或可用性要求 |
|---|---|---|---|
| 支持 Agent Skills 的宿主 | 是 | 读取技能、检查原图与候选、交付结果 | 必须能读取图片并完成视觉 QA。 |
| 宿主图像编辑能力 | 默认通道需要 | 编辑当前目标原图 | 能执行基于原图的图像编辑，如 Codex 的 `image_gen`。 |
| Node.js / npm | 仅 CLI 安装需要 | 运行 `npx skills` | 可运行 Skills CLI；Git 或手动安装不需要。 |
| Python 与 API 依赖 | 仅 API 通道或本地 API 测试需要 | 执行编辑脚本和测试 | Python 3.9+；PyYAML ≥6.0、requests ≥2.32、Pillow ≥10.0。 |
| 同步图像编辑 API | 仅 API 通道需要 | 上传原图并获取候选 | 支持 OpenAI Images `/images/edits` 协议及本次所需参数。 |

用户配置固定为 `~/.config/polarisark-product-beautifier/config.yaml`，独立于技能安装目录。

| 配置项 | 默认值 | 设置位置 | 对结果的影响 |
|---|---|---|---|
| `backend` | `host` | 本地 YAML 或本次请求 | 选择 `host` 或 `api`。 |
| `api.base_url` | 无 | 本地 YAML | API 根地址，包含服务所需路径前缀；不填写完整 `/images/edits` 地址。 |
| `api.model` | 无 | 本地 YAML，可由本次请求覆盖 | 指定请求模型，不预设服务商或模型。 |
| `api.api_key_env` | `BEAUTIFIER_API_KEY` | 本地 YAML | 指定存放实际密钥的环境变量名；密钥不写入 YAML 或技能包。 |
| 比例、阴影、尺寸、质量与格式 | 比例 1:1、极轻接触阴影；API 可选参数默认不发送 | 本次请求 | 须与所选通道能力相符，实际像素与格式需核验。 |

**配置优先级：** 本次用户明确指定的方式与参数 → 本地配置 → 默认 `host`。本次覆盖不写回配置；安装、更新和重装不修改配置文件。缺少 API 配置或密钥时不发送请求，配置无效时不静默降级。

选用 API 时，在虚拟环境和技能目录内安装依赖并检查本地配置：

```bash
python3 -m pip install -r scripts/requirements.txt
python3 scripts/image_api.py --check --backend api
```

`--check` 不联网、不生成图片，也不证明远端服务可用。完整配置、调用和兼容范围见 [API 编辑说明](references/api-edit.md)。

**联网与费用：** 安装和更新需要访问仓库及相应安装源。宿主编辑的联网、账户与费用由宿主决定；API 模式连接用户配置的服务，每次生成或纠正都可能收费。超时或结果获取失败也可能已生成或收费，不自动重复提交。

**数据流向：** 宿主通道将目标原图和明确关联的参考图交给宿主编辑工具；API 通道将这些图片及内部精修指令上传至所配置服务，并将候选保存到调用指定的本地临时目录。宿主完成 QA 后交付成片并清理候选与中间资产；内部 Prompt、蒙版及其他中间资产不作为交付物。

## 7. 验证与问题排查

### 怎样判断结果合格

- 成片与对应原图仍为同一商品和 SKU；结构、颜色、部件、Logo 和文字符合真实性要求。
- 图片可打开，商品完整，材质自然，无明显变形、色偏、灰雾、硬边、重复纹理或新增物体；背景、比例和阴影符合请求。
- 文件名、实际格式和输入对应关系正确；每张目标图有结果，失败、结果未知和未处理项有明确说明。
- 可检查像素时，空白背景样本的纯白与白等效像素合计不少于 99%，且无可见色偏或灰块。白等效指各通道为 253–255、最大通道差不超过 2；完整判定见 [SKILL.md](SKILL.md)。

**最小验证请求：** 附上一张结构与颜色清楚的 `photo.jpg` 商品实拍图，输入：

```text
使用 $polarisark-product-beautifier 精修 photo.jpg，保持所有部件和摆放不变，输出 1:1 白底图。
```

**通过条件：** 返回通过 QA 的成片及摘要，保留商品事实和摆放，命名为 `photo_beautified` 加实际格式扩展名；未通过时说明具体失败原因。

**验证方式：** 成片质量使用上述人工样例和逐图视觉 QA。仓库另有 [API 本地测试](tests/test_image_api.py)，在安装 API 依赖后从仓库根目录运行：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py'
```

这些测试使用本地模拟 HTTP 服务，检查配置、上传顺序、错误分流、不自动重试、凭据处理、实际尺寸与格式及文件不覆盖；不调用真实服务，也不验证精修视觉质量。

### 常见问题

| 现象 | 先检查 | 处理办法 |
|---|---|---|
| Skill 未识别或未调用 | 宿主支持情况、安装范围、技能名及启用状态 | 确认安装目录有 `SKILL.md` 和配套资源；在 Codex 显式调用 `$polarisark-product-beautifier`。 |
| 原图无法读取或角色不清 | 图片路径、附件可用性、目标与参考图归属 | 补充可读取原图并确认角色；不靠文字描述猜测商品。 |
| API 配置或密钥缺失 | 固定配置路径、字段及指定环境变量 | 按 API 说明补齐；先执行本地 `--check`，它不验证远端服务。 |
| API 超时或结果未知 | 错误状态、是否已有候选或服务记录 | 说明可能已生成或收费，获授权后再处理，优先检查已有候选。 |
| 商品细节改变或成片不合格 | 原图、失败细节、已用纠正次数 | 在剩余额度内从原图定向纠正；上限后仍未通过则说明失败。 |

**报告问题：** 通过 [GitHub Issues](https://github.com/jonathansong21/polarisark-product-beautifier/issues) 提供宿主及版本、技能版本或 commit、脱敏素材、通道、复现步骤、错误状态和预期结果；不要提交密钥或其他凭据。

**SkillHub 发布：** 发布元数据统一维护在 [skillhub.yaml](skillhub.yaml)，字段含义见 [SkillHub 发布指南](https://skillhub.cn/tutorials)。源文件 `SKILL.md` 保留标准 Agent Skills frontmatter，避免 SkillHub 扩展字段导致标准校验失败。

发布前创建临时副本，包含 `SKILL.md`、`README.md`、`skillhub.yaml`、`LICENSE.md`、`agents/`、`references/`、`scripts/` 和 `tests/`；将 `skillhub.yaml` 的字段合并到副本 `SKILL.md` 的顶层 frontmatter，保留现有 `name`、`description`、`metadata` 与完整正文。合并时使用单行标量和行内列表，以兼容 SkillHub CLI 的解析方式；不得覆盖源目录或复制用户配置、密钥及 Git 数据。

源目录通过标准技能校验后，对发布副本执行 `skillhub publish <发布副本目录> --dry-run`。预检通过后，用户明确要求发布时再执行正式发布；版本更新只修改 `skillhub.yaml` 中的 `version`，保持 `slug` 不变。

**已知限制：** 图像编辑结果仍需对照原图 QA，细小文字、复杂连接、透明区域和高光材质可能无法在纠正上限内保真。API 仅支持同步原图编辑协议，不支持仅聊天兼容、纯文生图或异步任务接口。实际分辨率与模型信息以可核验结果为准，不能依据 Prompt 或请求模型名称声称达到某项规格。
